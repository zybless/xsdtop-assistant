# 修改和删除标签

这是修改标签目录本身；调整某道题绑定的标签仍使用题目编辑工具。新增、修改、删除分别授权，已有新增能力不会自动获得后两项能力；私库能力不能管理公共标签。

## 修改

1. 确认学科与准确目标。同名标签须按完整父级路径区分，不能猜编号。已知编号的停用标签也可以读取编辑快照。
2. 调用 `get_label_edit_snapshot`，保留未改名称和属性；用返回 `version` 作为 `update_label.expectedVersion`。名称必传，其他字段仅传需要更改的项；提示或说明传空字符串可清空，省略则保留。
3. `update_label` 沿用后台的父链、类型、同级重名、挂题及禁用规则。版本冲突后重读并合并所需修改，不能只更换版本重发旧内容。超时后重试完全相同参数，服务端回放事务回执。

## 删除

1. 调用 `preview_label_delete`。向老师展示学科、标签名称、完整父级路径、直接子标签数、全部后代数、关联题目数、软删除方式及阻止原因。预览只读。
2. 有子标签或题目绑定时不可删除，工具不发确认编号。不能自动改用整树删除、解除绑定或删除题目来绕过限制。
3. 展示上述实际影响后，暂停等待老师明确确认。笼统的整理、清理或先前授权不代替本次影响确认。
4. 确认后调用 `delete_label`，仅传预览返回的 `validationId` 和 `confirm: true`。目标、版本和学科固定在30分钟有效的记录内，不能替换。当前权限或绑定身份变化时重新核对。
5. 正式删除会再检查当前版本和后台规则；若影响变化，重新预览、展示并确认。只软删除该节点，不级联删除，也不删除题目或解除绑定。
6. 超时或结果未知时沿用同一确认编号重试，服务端回放原事务回执；不能为了重试重新预览生成新请求。确认记录过期或不可用时，先查明原结果再决定后续操作。

完成后用普通中文报告受影响标签及数量，不把内部编号当名称展示。
