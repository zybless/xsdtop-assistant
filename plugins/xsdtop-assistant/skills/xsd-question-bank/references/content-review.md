# 存量内容校对与修后验证

先确认本次是只读体检、格式修复还是内容订正，明确学科、题单/题目/讲义范围及需要保留的字段。按主 skill 核对密钥权限。只检查指定范围，先统计再分页获取必要明细，不默认全库导出。

## 区分问题，保留原意

| 类别 | 检查重点 | 处理 |
|---|---|---|
| 显示格式 | 公式定界、KaTeX不支持宏、小问分行、表格/选项、坏图、截断、重复标题 | 在授权内修显示，保持数学语义和判分内容 |
| 内容错误 | 条件缺失、数值/符号矛盾、题解串题、答案与图不一致 | 对照源文件与独立验算，单独列订正建议 |
| 无法恢复 | OCR丢失、找不到原图、缺页、不可辨认公式 | 标明缺失和来源，不猜测补全文字 |
| 元数据 | 标签、难度、来源、公开状态 | 只有本次范围包含时才修改 |

答案中的 `1mm`、`1 mm` 等可能是判分的可接受写法，不能为美观批量改成公式、删同义答案或重排空号。填空宽度、分数、选项顺序、题号和原句措辞同样不能作为格式整理的附带改动。

知识库正文、题干、选项、答案和解析应分开记录；相邻题的答案和图不能按位置盲配。讲义的概述与目录文本不是题目，也不应继承题目答案。

## 修复前的证据

用当前只读工具读取准确目标、原文及完整数组。保存本地审核清单：问题位置、原文、拟修改文本、来源依据、确定性及未修改部分。凭据与学生个人信息不进入清单或日志。

长文本修复保留原始字节或摘要供并发核对，避免拿旧快照覆盖另一会话的新内容。不要从压缩后的生产 JS bundle 猜导出函数来取数据：同名短函数可能实际是删除接口。题库读写坚持已有 MCP 工具。

## 写回与核验

只读检查不等于写授权。明确要求修正且目标已确定时，在授权范围内使用 `update_question`；发送前再次比较当前内容与审核底稿，变化时停止该题并重算补丁。客户端比对不能声称提供原子的并发保护。

`options`、`answers`、`analyses`、`labelIds` 是完整替换数组，保留未修改项、顺序和正确项标记；不要发送空数组当“未修改”。格式修复不顺带清理标签或重复解析；删除按主 skill 单独确认。写结果不明确先回读，不盲重试。

每次写后回读核对目标字段与拟改结果逐字一致，并验证其余字段、答案空号、选项数量、图片归属及公开状态。实际渲染可用时复查异常片段；工具不支持预览就明确“结构已核验，页面显示待验”，不伪称看过。

知识库的正文评审只产出本地修订稿和清单。没有对应写工具时报告能力边界，不能借用题目更新接口，或擅自调用知识库HTTP接口。

## 老师明确要SQL时

沿用主 skill 的只读结构核查与SQL交付流程。针对真实目标生成精确限定的补丁、执行前检查、执行后验证及必要的反向补丁；摘要守卫或HEX字面量以真实字段、编码和SQL模式为准，验证往返不丢反斜杠。

不新建备份表、临时表或修改表结构；本地原文快照即可留底。不要运行历史大表 CTAS 备份。SQL仅交老师在插件外执行；只读查询工具不能执行写SQL，也不能声称文件已生效。检索投影、缓存或内容哈希如何更新必须查当前实现，不能照搬历史一次性回填命令。

最终用中文报告已检查数量、确定问题、已修正数量、未核验和待教研事项；分开说明“生成修复稿”“已写回”“已回读验证”，不混成一句完成。
