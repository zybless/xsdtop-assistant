# 本地阅卷报告质量要求

本文件随插件分发，下载资料包时保存为 `report-guidelines.md`，下载结果的 `reportGuidelinesPath` 指向该文件。它规定现有结果字段如何写实、写清楚，不改变题单评分、教练说明或待复核语义，也不要求本机安装网站源码。字段类型和容量见技能内的 `references/result-format.md`；当前外部协议没有 `analysis`、`subItems`、`writing` 等字段，不自行添加。

## 从证据到诊断

先实际查看答卷，确认题号和页码，再判断有效过程与结论，最后归纳整卷。学生采用与解析不同的有效方法，不是错误；评分仍以真实题单和教练口径为准。没有细分标准时，不把自己的步骤划分写成老师已确定的评分细则。

与站内阅卷共用证据、有效方法和待复核原则，字段按本地协议填写：站内的 `sortOrder`、`gotScore` 在本地分别为 `itemNo`、`score`；不复制站内的 `analysis`、`subItems`、`writing`。站内默认的0.5分步长也不套用到本地，本地按真实 `rubric.json` 与教师说明判分。教师说明不改变证据状态，无法辨认或缺页不能被要求成零分。

- `studentAnswer` 忠实记录可辨认的作答，保留学生算错的式子、符号和结论；不能把推测补成原文。结合上下文仍看不清时，明确不确定之处。
- `reason` 用简短文字指出可核对的具体环节，例如“关系式正确，最后把2×3算成了5”。不要只写“错误”“粗心”“基础薄弱”，也不在其中展开长推导或复述分数。
- `topicDirection` 写本题实际考查的知识或方法，不用笼统的“综合能力”。题目已匹配且方向可确认时应填写。
- `didWell` 写卷面确实成立的一步或方法；`toImprove` 写问题发生在哪里、为什么不成立、下一步怎样改。复杂公式和必要的短推导可放在这些字段及报告正文中。
- `rootCause` 是有证据支持的归因。一次计算错误不足以断言概念薄弱、习惯差或注意力不足；无法区分时可省略。
- `pageNos` 使用实际原始答卷页码，便于教师回看；不填原卷或答案解析的页码。

## 按作答状态提供内容

| 情况 | 诊断内容 |
| --- | --- |
| 已作答、全对 | 写清已体现的方法或关键步骤；没有实际问题时不硬写 `toImprove`，不制造短板。 |
| 已作答、部分正确或错误 | 指向真实证据，给出可执行的改法；有有效步骤才写 `didWell`，没有时可缺省，不凑亮点。 |
| 确认真实空白 `BLANK` | `reason` 说明没有作答；计分时0分、判错。可以依据题干给入手建议，但应说成建议，不能说成学生已经做过的过程或不会的知识。 |
| `UNREADABLE`、`MISSING_PAGE`、`UNMATCHED` | `score`、`judge` 均留空。说明哪一部分看不清、缺失或无法匹配，以及复核所需材料；不把资料问题归为知识短板，不编造解题诊断。 |

整卷有待复核题时，在报告开头说明结论仅覆盖可确认的作答，并列出待复核题号。真实空白题与无法确认作答的题分别说明；不要混称“未掌握”。

## 报告要能独立阅读

`reportMd` 面向学生和家长，单独打开也应知道这次做到了什么、哪里需要调整、下一步怎么练。建议按“整体情况 → 逐题表现 → 共性问题与训练建议”组织，篇幅随答卷证据变化，不凑章节、字数或优缺点条数。

逐题概况覆盖所有题号；对需要改进的已作答题给出足够的具体解释，不能仅写“详见解析”。全对题可以简洁，复杂证明可以展开；待复核题只说明材料限制。正文与 `items`、`overallComment`、`strengths`、`weaknesses`、`suggestions` 使用同一事实，不在一个地方判错、另一个地方夸全对。

整体总结由逐题证据归纳。亮点和薄弱点尽量关联题号，区分共性与个别问题。训练建议对应已确认的问题，给出适当的任务、题量或难度，以及怎样自查；例如“先重算第1题，再做2道同类基础题，逐步核对单位和运算”。全对或证据有限时按实际写，不强凑两到四条。

正文、诊断及整卷总结不复述总分、逐题得分或得分率，成绩由网站展示。数学中的分数、比例和百分数可以正常使用。`referenceDoubt` 仅用于教师复核参考答案，不进入公开正文；公开文本也不包含内部批改讨论、模型身份或教师裁决请求。

## 公式与保存

短表格和 `reason` 使用简洁文字、普通算式，如 `1/15`、`2×3`；复杂分式、根式、上下标和推导放正文，用 `$...$` 表示行内公式，较长推导用独立行的 `$$...$$`。公式定界符必须成对，LaTeX 命令放在公式内部；不要用代码围栏显示数学公式，不在窄表格中堆长式子。

排版可以统一单位和公式写法，但不能改变学生原始作答的数学含义。说明正确方法时，与学生原式分开写清楚，不能将错误转写直接替换为正确结果。

使用 JSON 序列化器写文件，避免 `\frac` 的 `\f`、`\times` 的 `\t` 等被误写成控制字符。不要全局翻倍或删掉反斜杠；修复后重新解析并检查显示效果。

## 校验后的检查

`validate_*_grading_results` 保留 `successes`、`failures`、`pending`，新增 `reports` 数组，每项包含 `submissionId`、`quality`（`errors`、`warnings`）、`previewPath` 和 `qualityPath`，并保存 `quality/<submissionId>.json` 和 `previews/<submissionId>.html`。确定的公式语法错误、异常控制字符等会阻止该份远端校验及回写，先修正再校验。

诊断缺项等警告不直接阻断。逐条核对后，补齐能由证据确认的内容；确实无有效步骤或证据不足时保留缺项，在本地交付说明中解释，不能为消除警告制造结论。查看预览中的公式、换行、表格与逐题内容，修改结果后重新校验。

本地预览采用基础 Markdown/KaTeX，能发现明显的公式与排版问题，但不证明网站、手机端、PDF 三个出口效果完全一致。已有“批改并回写”授权且检查完成时继续回写，无需为了预览新增确认步骤。
